# RK3568 Qt 交叉编译离线技术说明

本文将 Qt、CMake 与 RK3568 官方公开资料整理为中文操作说明，供离线交付使用。

## 1. 交叉编译的三个对象

- **主机**：运行编译器的 Ubuntu 24 电脑；
- **目标板**：运行应用的 RK3568 Linux 设备；
- **sysroot**：目标板文件系统中“头文件和库”的本地副本。

交叉编译器在主机运行，生成 ARM64 文件；sysroot 确保编译器链接的是目标板库，而不是主机 x86_64 库。

## 2. sysroot 的正确来源

目标板通常没有名为 `sysroot` 的目录。板端 `/usr/lib`、`/usr/include` 等目录组成运行时环境；一键脚本将其同步到主机，生成 sysroot。

sysroot 必须与部署目标保持一致，包括：系统版本、glibc、Qt、EGL/GLES、DRM、输入库和 GPU 用户态库。不要混用 RK3588 与 RK3568 的图形和硬件加速库。

## 3. CMake 工具链的作用

工具链文件固定以下信息：

- 目标系统是 Linux；
- 目标架构是 aarch64；
- C/C++ 编译器是 `aarch64-linux-gnu-gcc/g++` 或厂商 SDK 编译器；
- `CMAKE_SYSROOT` 指向目标 sysroot；
- 查找头文件、库和 CMake package 时只使用目标 sysroot；
- `pkg-config` 的搜索路径只使用目标 sysroot。

这样可避免链接到主机的 x86_64 `libEGL`、Qt 或 OpenSSL。

## 4. Qt host 与 target 的对应关系

如果只编译 Qt 应用，可直接使用目标 sysroot 中匹配的 Qt 开发包。

如果从源码构建 Qt，本机 Qt host tools 与目标 Qt 必须使用同一版本。`moc`、`rcc`、`qmlcachegen`、`qsb` 在主机运行；Qt 库和平台插件在 RK3568 上运行。Qt Quick 项目还需要 host 侧的 `qsb`。

## 5. 选择显示后端

| 目标环境 | 建议 Qt 平台 |
| --- | --- |
| 单应用全屏、DRM/GBM 可用 | `eglfs` |
| 已有 Wayland 合成器、多应用窗口 | `wayland` |
| 已有 X11 桌面 | `xcb` |
| 仅 framebuffer，先验证显示 | `linuxfb` |

`eglfs` 不依赖 X11 或 Wayland，适合设备单应用全屏。它通常只有一个原生全屏窗口；多应用或复杂窗口管理使用 Wayland。

## 6. RK3568 适配重点

RK3568 是 ARM64 Cortex-A55 平台，集成 Mali-G52 GPU、4K 级视频处理和 NPU。Qt 应用的业务源码、CMake 结构和 ARM64 交叉编译方法可与 RK3588 共用；GPU、EGL、DRM、显示设备树、RGA、MPP、V4L2、DMA-BUF、RKNN 必须以 RK3568 系统/BSP 为准。

首次构建不使用 RK3588 专用 CPU 参数，例如 `-mcpu=cortex-a76`。建议先采用工具链默认 ARM64 参数，完成目标板验证后再做优化。

## 7. 构建与部署检查

构建成功后：

```bash
file <应用程序>
```

应显示 `ARM aarch64`。部署到目标板后：

```bash
ldd <应用程序>
QT_DEBUG_PLUGINS=1 QT_QPA_PLATFORM=eglfs <应用程序>
```

若出现 Qt 平台插件、EGL 或库文件错误，先检查 sysroot 和目标板的 Qt/GPU 库版本是否一致，再检查平台插件选择。
